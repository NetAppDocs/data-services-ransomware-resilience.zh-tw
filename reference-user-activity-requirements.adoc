= NetApp Ransomware Resilience 的使用者活動偵測需求
:hardbreaks:
:allow-uri-read: 
:icons: font
:imagesdir: ./media/


[role="lead"]
NetApp Ransomware Resilience 使用者活動偵測使您能夠回應使用者層級的勒索軟體事件。您必須建立租戶和一組代理程式才能啟用使用者活動偵測。在啟用偵測之前，您必須確保您符合規定的作業系統、伺服器和網路要求，以便 Ransomware Resilience 能夠正確偵測和報告事件。



[[user-activity-tenant]]
== 使用者活動租戶

為了啟用使用者活動偵測，系統會設定一個租戶，允許將使用者活動事件與 Ransomware Resilience 共享的。您可以選擇 Ransomware Resilience 部署該租戶的區域和雲端供應商。


NOTE: 租戶的區域部署對 Console 代理程式沒有影響。Console 代理程式的部署與這些區域無關。

租戶可以部署在 AWS 和 Azure 的以下區域：

|===
| 雲端提供者 | 地區 


| AWS  a| 
* 亞太地區（雪梨）（ap-southeast-2）
* 歐洲（法蘭克福）(eu-central-1)
* 美國東部（維吉尼亞北部）（us-east-1）




| Azure | 美國東部 
|===


[[user-activity-agent-requirements]]
== 使用者活動代理程式需求

建立租戶後，您必須建立使用者活動代理程式以啟用使用者活動偵測。使用者活動代理程式並非 Console 代理程式；使用者活動代理程式需要部署為分隔的運算執行個體。

請確保您的使用者活動代理程式符合以下要求並遵守相關建議。

| CentOS | CentOS Stream 9（64 位元） 


| Debian | 11（64 位元）、12（64 位元），包括 SELinux 


| OpenSUSE 飛躍 | 15.3（64 位）至 15.6（64 位） 


| Oracle Linux | 8.10（64 位元）、9.1（64 位元）至 9.6（64 位元），包括 SELinux 


| Red Hat Enterprise Linux | 8.10（64 位元）、9.1（64 位元）至 9.6（64 位元）和 10（64 位元），包括 SELinux 


| 洛基 | 9.4（64 位元）至 9.6（64 位元），包括 SELinux 


| SUSE Linux Enterprise Server | 15 SP4（64 位元）至 15 SP6（64 位元），包括 SELinux 


| Ubuntu | 20.04 LTS（64 位元）、22.04 LTS（64 位元）和 24.04 LTS（64 位元）

NOTE: 用于用户活动代理的计算机不应运行其他应用程序级别的软件。建議使用專用伺服器。

安裝需要  `unzip` 命令。安裝、執行指令碼和解除安裝需要  `sudo su -` 命令。



[[server-requirements]]
=== 伺服器要求

伺服器必須滿足以下最低要求：

* CPU：4 核
* **內存**：16GB 內存
* **磁碟空間**：36 GB 可用




==== 伺服器建議

* 分配額外的磁碟空間以建立檔案系統。確保檔案系統中至少有 35 GB 的可用空間。+ 如果 `/opt`是從 NAS 儲存設備掛載的資料夾，則本機使用者必須能夠存取此資料夾。如果本機使用者沒有必要的權限，則使用者活動代理程式建立可能會失敗。
* 請將使用者活動代理程式安裝在與您的 Ransomware Resilience 環境分隔的系統上。如果您確實將代理程式和 Ransomware Resilience 安裝在同一台機器上，請預留 50 至 55 GB 的磁碟空間。對於 Linux，請分配 25 至 30 GB 的空間給 `/opt/netapp`，並分配 25 GB 給 `/var/log/netapp`。
* 建議您使用網路時間協定 (NTP) 或簡單網路時間協定 (SNTP) 同步ONTAP系統和使用者活動代理程式電腦上的時間。




==== 大小調整建議

收集使用者事件時，請確保代管使用者活動代理程式的機器大小足以容納您的事件率。這表示您需要確保代管使用者活動代理程式的機器擁有足夠的資料收集器，以及足夠的 CPU 和 RAM，以處理每秒的事件數。若要增加資料收集器的數量，您可能需要增加 RAM 或 CPU 容量。Ransomware Resilience 每個使用者活動代理程式最多支援 50 個資料收集器。

下表提供大小調整的一般指引：

|===
| 使用者活動代理程式機器組態 | 資料收集器數量 | 最大事件速率 


| 4 核心，16 GB | 10 個資料收集器 | 每秒 20,000 個事件 


| 4 核心，32 GB | 20 個資料收集器 | 每秒 20,000 個事件 
|===
您也可以計算您的具體需求。計算適當的容量時，建議預留 30% 的緩衝率。使用此公式來確定您的配置是否能夠承受負載。

[listing]
----
Where E is the sum of all events per second across all data collectors:

E + (0.3 x E) < 20,000 events/second
----
.計算 Ransomware Resilience 中的事件資料速率
[%collapsible]
====
Ransomware Resilience 提供了一個指令碼，您可以在系統上執行該指令碼來計算事件資料速率。預設情況下，指令碼最多可針對五個 SVM 執行。如果您的環境包含超過五個 SVM，您可以相應地修改指令碼。無論 SVM 的數量為何，指令碼大約需要五分鐘才能取得平均事件速率讀數。在執行指令碼之前，您必須具備：

* link:suspicious-user-activity.html["已設定使用者活動代理程式"]
* 叢集 IP 位址
* 叢集管理使用者名稱和密碼
* 已在 Linux 機器上安裝 `sshpass`（您可以使用命令 `sudo yum install -y sshpass`進行安裝）


.步驟
. 在託管使用者活動代理程式的電腦上，以管理員身分執行指令碼： `/opt/netapp/cloudsecure/agent/install/svm_event_rate_checker.sh`
. 出現提示時，請提供叢集 IP 位址、管理員使用者名稱和管理員密碼。
. 該腳本大約需要五分鐘才能執行完畢。執行完成後，命令列會顯示事件速率，例如「Svm svm_rate 正在產生 100 個事件/秒」。
+
使用事件速率來計算您的大小。

| TCP | 35000-55000  a| 
SVM 資料 LIF IP 位址
| 使用者活動代理 | 從 ONTAP 到使用者活動代理程式的 FPolicy 事件通訊。必須對使用者活動代理程式開放這些連接埠，以便 ONTAP 可以向其傳送事件，包括使用者活動代理程式本身的任何防火牆（如果存在）。+ **注意：** 您無需保留*所有*這些連接埠，但為此保留的連接埠必須在此範圍內。建議您先保留 100 個連接埠，並在必要時增加。
